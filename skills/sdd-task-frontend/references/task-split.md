# 前端 Task 切分细则

本文件是 [SKILL.md](../SKILL.md) Step 6 的细则。设计依据是 `sdd-dev-frontend/references/sdd-task-frontend-split.md`——那份原本是写给上游的需求说明书，本文是它的**可执行版本**；两者冲突时以本文为准。

## 一、为什么按形态切，不按功能点切

前端有两类工作，因果证据意图不同：

| 工作类型 | 计划声明 | 执行侧证明 |
| --- | --- | --- |
| 还原（把静态呈现落成组件代码） | 外部设计事实、页面 / 区块边界、需成立的还原声明 | 为声明编译契约、渲染或视觉证据；不适用的动作不执行 |
| 逻辑补全（状态迁移、条件渲染、数据变换、接口交互） | 行为缺口、关键断言与可观察结果 | 为声明编译最窄的因果证据；证据形态由下游决定 |

冻结契约的对照对象是**整块区块**，所以它只有在「该区块的样式在这一轮全部落地」时才能整体 GREEN。按功能点切（每个 Task 带一点样式加一点逻辑）产生三个后果：

| 后果 | 说明 |
| --- | --- |
| 机器报告反复失效 | 同一区块在后面的 Task 里又被动样式，前一轮 GREEN 不再代表最终实现 |
| 重复取证 | 每个碰样式的 Task 都要重跑完整契约，成本按 Task 数增加 |
| 责任不清 | 一处间距错了，归属哪个 Task 的 RED 没有定论 |

结论：**整页样式集中在一个 Task 里落地，之后的 Task 只加行为、不动样式。**

这与「一个 Task 内允许多轮 6 步」不冲突：**按形态切是首选，多轮 6 步是切不开时的兜底。**

## 二、五条要求

### 要求 1 — 一个页面的样式集中成一个独立的还原 Task

1. 每个页面先出一个**还原 Task**，把该页面全部区块的静态结构与样式一次落完，含五态样式（hover / focus / disabled / 选中 / loading）与空态、超长文案、超多条目的静态呈现。
2. 该页面的行为再切成若干**逻辑 Task**，按 AC 分组，一个 Task 覆盖一组紧邻的 AC。
3. 同一页面的还原 Task **必须排在它的全部逻辑 Task 之前**——行为要挂在 DOM 上，没有结构就没有挂点。
4. **一个 Task 只承担一种形态。** 确实切不开的区块（样式由运行时状态计算得出，静态形态不存在）留在逻辑 Task 里，注明「本 Task 含还原轮」，按多轮 6 步执行。

第 4 条留的口子**必须写明理由**，否则「切不开」会变成不想切的挡箭牌。

### 要求 2 — 跨页公共样式与骨架单独一个 Task，排在最前

本 Story 涉及多个页面且共用布局骨架、公共展示组件或需要新增样式 token 时，先出一个**公共样式与骨架 Task**，排在全部页面 Task 之前，一次落完：新增或改动的 token、公共布局组件、跨页复用的展示型组件。

不单列这一个 Task，第一个页面的还原 Task 会顺手把公共件建出来，第二个页面再按自己的形态改一次，两个 Task 的机器报告互相推翻。

### 要求 3 — 还原 Task 独占样式文件

还原 Task 的文件清单必须列出该页面全部样式文件与组件骨架文件。

**逻辑 Task 的文件清单不得包含样式文件。** 确有必要时（典型：新增状态类名需要配套样式），在该逻辑 Task 下显式写一行：

```
越界改样式：<文件> — <原因>；影响 Task <编号> 的 GREEN 报告
```

文件清单是执行侧「修复动作不出本 Task 的文件清单」的边界。把样式文件的归属写进计划，等于把「谁有权动样式」写死；例外要求显式登记，是为了让需要重跑的冻结契约有据可查，而不是让既有 GREEN 报告悄悄失效。

### 要求 4 — 还原 Task 必须给出视觉来源（**不给锚点**）

每个还原 Task 逐区块注明三项：

| 项 | 内容 |
| --- | --- |
| 原型文件 | 第 1 档时的原型文件路径；第 2 档写参照页路由；第 3 档写文字规格章节号 |
| 页面 / 路由 | 该区块所在的路由 |
| 区块名 | 一个名词短语，视觉职责单一（「筛选栏」「订单卡片」，**不是**「筛选栏和列表区」） |

**不产出 class 锚点。** 锚点由下游 `sdd-dev-frontend` Phase A1 的 `extract_design_spec.py` 与 `extract-prototype` 确定性生成；计划阶段算第二份必然与它冲突。已存在 `design-spec/` 时可以引用其区块名，但不复制锚点。

> 这一条是本文与设计依据的**唯一实质差异**。原文要求逐区块给出 class 选择器锚点与行号范围，那是只有抽取脚本才算得可靠的东西——原文自己也承认单行导出件上行号跨度恒为 `L1-L1`。让计划阶段产出只有执行阶段算得出的东西，是那份说明书一直落不了地的原因之一。

**区块粒度的判据**是「视觉职责单一、可由一组契约规则完整覆盖」：职责能用一个名词短语说清，规则无需跨不相关区块才能判定。

**不用行数当判据**：同一屏内容在压缩过的 HTML 里可能是 1 行，在格式化模板里可能是 400 行。实测一份 269,198 字符、10.4 屏的设计稿导出件总共只有 2 行——这不是极端情况，是主流设计工具导出的默认形态。

规模只作提示：单个区块的**组件实例数**明显偏多（经验值 20 个以上）或**元素节点数**明显偏大（经验值 200 个以上）时，在该区块下写一行「不拆的理由」。超过它不一定要拆，但要显式说明为什么不拆。**不要用行号跨度当这个提示指标。**

一个页面默认一个还原 Task。拆成多个的唯一合法边界是区块边界，触发条件是该页原型分散在多个原型文件、或区块多到一轮契约检查改不完；**不得按「先出骨架、后细化样式」拆成两遍**——那样第一轮契约必然留下 RED，从计划阶段就注定卡住。

### 要求 5 — 禁止收尾性质的样式 Task

不得产出「样式微调」「统一优化样式」「视觉走查修复」这类 Task。样式偏差的修复归属于它所在区块的还原 Task，当轮让同一冻结契约整体 GREEN。

这类 Task 没有可对照的原型范围，冻结契约无从运行，Step ① 立不起来。它的实际作用是给前面几轮留一个「以后再说」的出口。

## 三、正反例

同一个「订单列表页」Story。

**反例（按功能点切）**

```
T1 订单列表页 — 列表区（样式 + 取数 + 分页）
T2 订单列表页 — 筛选栏（样式 + 筛选逻辑）
T3 订单列表页 — 详情抽屉（样式 + 详情取数）
T4 样式统一优化
```

问题四处：三个 Task 都动样式，跨区块的间距与字号一致性无人负责；T1 的 GREEN 报告在 T2 加完筛选栏样式后失效；T3 的抽屉与列表区共用的卡片样式归属不清；T4 没有冻结契约范围。

**正例（按形态切）**

```
T1 订单列表页 · 还原
   视觉来源：order-list.html（第 1 档）
   路由：/orders
   区块：页头 / 筛选栏 / 列表区 / 分页 / 详情抽屉
   文件：OrderList/index.tsx、OrderList/index.module.css、OrderList/components/*（骨架）
T2 订单列表页 · 列表取数与分页（AC-1.1、AC-1.2）
   文件：OrderList/index.tsx、api/order.ts、hooks/useOrderList.ts（不含样式文件）
T3 订单列表页 · 筛选与重置（AC-1.3）
T4 订单详情抽屉取数（AC-2.1）
```

T1 一轮还原覆盖全页，冻结契约一次闭环；T2–T4 只挂行为，不动样式。注意 T1 **没有写 class 锚点**——那是下游 Phase A1 的产物。

## 四、切分自查

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 形态纯化 | 每个前端 Task 只承担一种形态；含还原轮的逻辑 Task 已注明理由 |
| 2 | 还原覆盖面 | 每个页面有且只有一个还原 Task（或按区块边界拆出的多个），覆盖该页全部区块；判定无静态呈现时已写理由 |
| 3 | 顺序 | 同页还原 Task 在其全部逻辑 Task 之前；公共样式与骨架 Task 在全部页面 Task 之前 |
| 4 | 文件清单归属 | 逻辑 Task 无样式文件，或例外已按要求 3 登记 |
| 5 | 视觉来源 | 每个还原 Task 逐区块给了原型文件 / 参照页 / 文字规格章节 + 路由 + 区块名；实例数或节点数偏大的写了不拆理由；**未出现 class 锚点** |
| 6 | 无收尾 Task | 全文搜「微调」「优化样式」「走查」，无命中 |
