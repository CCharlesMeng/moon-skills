# 因果证据意图与兼容 6 步

本文件是 [SKILL.md](../SKILL.md) Step 7 的细则。计划阶段只定义验收声明和证据意图；执行动作由 `sdd-dev-frontend` 根据风险触发器与最终 diff 编译。

## 一、兼容形状

保留 `sdd-task` 的 6 步 checkbox，使 `tasks.md` 继续承担执行顺序与进度真相。前端计划不在 checkbox 中写精确命令、浏览器矩阵、全量回归或独立检视；这些信息只有执行侧结合仓库环境才能正确决定。

每轮只写：

| Step | 计划写什么 |
| --- | --- |
| ① 暴露缺口 | 受影响的 AT-/AC、证据形态、改动前什么现象说明缺口存在 |
| ② 确认原因 | 什么现象才算“因正确原因失败” |
| ③ 最小实现 | 改哪些文件、达成什么可观察行为 |
| ④ 证明声明 | 哪些 AT-/AC 应变成 `PROVEN`、最小可观察结果是什么 |
| ⑤ 重构 | 按需；不预设动作 |
| ⑥ 记录并提交 | 引用 `alpha-tests.md` 证据账本并使用内联提交规范 |

Step ④ 只证明当前 Task 改变的声明。全量命令、状态矩阵、跨页回归与检视留给候选验证组合，不写进每个 Task。

## 二、证据形态

| 形态 | 何时用 | Step ① 写法 |
| --- | --- | --- |
| 逻辑 | 有用户行为、状态迁移、数据映射或接口分支 | 行为缺口 + 关键断言 + 候选测试位置；不写测试代码和命令 |
| 还原 | 改静态结构、样式、token 或可见文案 | 视觉来源 + 页面/区块 + 预期出现差异的声明；契约由下游冻结 |
| 机械 | 变化只涉及类型、构建或引用对齐，没有行为分支 | 编译/构建缺口 + 通过条件 + 为什么不需要行为证据 |

还原证据的期望来源必须在实现之外。计划不复制 R1–R6、契约字段、class 锚点或视觉数值。

## 三、多轮

优先按形态切 Task。确实切不开时允许同一 Task 多轮，默认先还原后逻辑；每轮引用自己的验收声明。两轮由同一组实现共同满足时可以共享 Step ③ 的实现意图，但不能把一边的证据当作另一边的证据。

计划不再判断“双通道快路径”。是否锁步、并行或复用动作属于执行策略，由下游验证组合决定。

## 四、自查

| # | 通过标准 |
| --- | --- |
| 1 | 每个 Task 都引用受影响 AT-/AC，并写明证据形态与可判定现象 |
| 2 | 全文没有精确验证命令、全量回归、浏览器矩阵或独立检视安排 |
| 3 | Step ④ 只证明当前 Task 的声明，不承诺 Story 级完成 |
| 4 | 还原轮无 class 锚点、契约字段和视觉数值 |
| 5 | 多轮之间不复制期望值，不预排锁步执行 |
