# Step ① 失败证据的两种形态与多轮 6 步

本文件是 [SKILL.md](../SKILL.md) Step 7 的细则。设计依据是 `sdd-dev-frontend/references/sdd-task-amendments.md`——那份原本是写给上游的回改说明书，本文是它的**可执行版本**。

## 一、为什么要两种形态

6 步 checkbox 要求每个 Task 从「写一个失败的测试」开始。这条纪律在后端和前端的逻辑类工作上都成立，但在**前端还原类工作**上不成立：

- 对着原型断言 DOM 结构，测试内容就是实现内容的照抄，红绿是走过场；
- 这类橡皮图章测试还会流进 `alpha-tests.md`，稀释它作为验收唯一证据源的分量。

所以：**保留 6 步的编号、顺序与 RED/GREEN 语义完全不变，只把 Step ① 的失败证据扩为两种形态。**

选冻结契约而不是实现侧 DOM 断言，关键理由是**它的基线在外部**：契约镜像的是经用户确认的 `dev-baseline.md` 与 Requirement 级设计事实，不是 Agent 根据当前实现反推的断言；契约与基线哈希不一致时必须硬失败。

### 被否决的三个替代方案

| 否决的方案 | 否决理由 |
| --- | --- |
| 还原也老实写 DOM 断言测试 | 形式统一，但产出橡皮图章测试并污染证据账本 |
| 还原不进 Task List，前移为独立前置阶段 | 6 步可原样保留，但还原工作会脱离 AC 追溯，「每条 AC ↔ 覆盖它的 Task」缺一角 |
| 强制把还原和逻辑拆成不同 Task | 前端 Task 的自然单位是一个页面或区块，天生同时含两者，按 Task 二选一是在假装它们能被切开 |

第三条被否决，直接推出**一个 Task 内必须允许多轮 6 步**。注意它与 [task-split.md](./task-split.md) 要求 1 不冲突：**按形态切是首选**，能切开就切开，多轮 6 步是切不开时的兜底。

## 二、Step ① 的写法

**前端 Task 每一轮的 Step ① 必须显式标注形态，不得省略。**

> **Step 1: 写失败证据（RED）— 形态：<逻辑 / 还原>**
>
> - **逻辑类**：测什么行为 + 关键断言 + 测试文件路径。不写完整测试代码。
> - **还原类**：运行已冻结的外部设计契约，生成 RED / YELLOW / GREEN 机器报告；至少一项明确 RED 才进入实现。注明**视觉来源**（原型文件 / 参照页路由 / 文字规格章节）与**区块名**。

两形态并列而不是二选一的注脚，是为了让写计划的 Agent 每一轮都被迫做一次显式选择，而不是默认走测试形态、遇到写不出测试时再临时找补。

**这里刻意不写契约的具体维度与 JSON 字段。** R1–R6 / F1–F4 及字段由下游的 QA 基线与契约规范提供，且要经人工确认门冻结；抄进计划会形成两处维护。计划只规定「运行冻结契约并得到明确 RED」。

**同样不写 class 锚点**（见 [task-split.md](./task-split.md) 要求 4）——锚点是下游 Phase A1 的产物。

## 三、粒度纪律

每步 2–5 分钟一个动作。「**写失败证据**」和「运行确认失败」是两步，不可合并。

注意措辞：是「写失败证据」，不是「写失败测试」。全文不应残留「写失败测试」——它把还原轮排除在外了。

## 四、一个 Task 内的多轮 6 步

**一个 Task 内允许出现多轮 6 步。** 前端 Task 的自然单位是一个页面或区块，可能同时包含还原与逻辑两类工作，二者各走一轮完整的 6 步。

- 默认顺序：**先还原轮、后逻辑轮**。物理依赖——行为通常要挂在 DOM 上，没有结构就没有挂点。
- 每一轮独立编号并标注形态：`Task 3 · 轮 1（还原）`、`Task 3 · 轮 2（逻辑）`。
- **6 步的编号、顺序、checkbox 与 RED/GREEN 证据链不得合并。**

### 双通道候选

两轮都满足下列全部条件时，可在该 Task 下标注「双通道候选」：

1. 两边都能在改产品代码前得到**原因独立**的 RED；逻辑 RED 不能只是因为待还原的 DOM 尚不存在；
2. 两轮预期由**同一组产品改动**共同满足；
3. 没有 YELLOW、fixture 冲突或待决策项。

标注的含义是「执行侧可以考虑锁步推进」，**不是命令**：下游会自行复核这三条，并保留两套独立的 RED/GREEN 与 checkbox。条件不满足时它回退默认顺序，这是安全分支，不算执行失败。

只有逻辑 RED 不依赖待还原结构、两边能共同实现时，锁步才减少重复实现与重构；所以这个标注要保守给，宁可不标。

## 五、与下游证据账本的衔接

计划阶段**不需要为此做任何额外产出**。`alpha-tests.md` 的既有四节结构保持不变，扩容由下游在执行过程中完成：

- 还原轮 Step ⑥ 的证据（契约哈希、RED / GREEN 报告指纹与路径、三色摘要、可选视觉缓存与实现截图）落在下游新增的「还原证据记录」节；
- 该节的记录编号被「AC ↔ 证据映射」节引用，`alpha-tests.md` 因此仍是验收追溯的唯一证据源。

计划阶段只要保证**每条 AT- 用例都有 Task 覆盖**，不要去预留证据表格。
