# 前端仓初始化

## 目标与边界

以**一个独立前端 app**为工作单位，产出 [references/baseline-contract.md](references/baseline-contract.md) 定义的九份文件，并把当前机器准备到能装、能起、能跑质量命令。单应用仓的 app 根就是仓根；monorepo 的 app 根是选中的子目录。“整体生成”只批量执行所有已选 app，各 app 的 baseline 仍彼此隔离。

执行前先完整读取该契约与 [references/discovery-rules.md](references/discovery-rules.md)。

| 事项 | 本 skill |
| --- | --- |
| app 级九份文件 | 负责，且**独占规范节的写权限** |
| 机器准备（装、起、必需服务与身份、质量命令实跑） | 负责 |
| 浏览器实证（截图、DOM 采集、视口与字体） | **不负责**，由 `sdd-dev-frontend` Phase 0 按当次 Story 是否需要视觉能力决定 |
| 需求级 `DEMAND-1~3` | 不负责，由 `sdd-dev-frontend` 在 Requirement / Story 生命周期生成 |
| monorepo / 跨仓拓扑 | 只负责识别 app 候选；拓扑由外层流程管理 |
| 仓内已有的规范文档 | 只读作线索并验证；**不改写、不删除**，已迁条目在收尾回话里列出 |

## 路径

| 变量 | 含义 |
| --- | --- |
| `<repo-root>` | Git 仓或 monorepo 根目录 |
| `<target-app>` | 目标 app 相对 `<repo-root>` 的路径；单 app 仓为 `.` |
| `<frontend-root>` | 目标 app 根目录；`<target-app>=.` 时等于 `<repo-root>`，否则为 `<repo-root>/<target-app>` |
| `<repo-baseline-dir>` | `<frontend-root>/frontend-baselines/` |
| `<candidate-ledger>` | `<repo-root>/.learnings/frontend-baseline-candidates.md`；化石候选台账，在 baselines 目录之外，只有本 skill 读写 |
| `<story-dir>` | 由 `sdd-dev-frontend` 路由进来时的 Story 目录；独立调用时不存在 |

先自动定位。monorepo 只有一个合理 app 时静默选择；有多个合理 app 时，一轮列出每个 app 和“整体生成（为全部 app 分别生成）”选项，未选择不继续，不默认把仓根当成整体 app。“整体生成”逐 app 独立执行本 skill，不把多个 app 写进同一目录。

## 硬门禁

1. **只指路不复制。** 能从某个文件里逐字读到的内容不写进 baseline，只写指路；必须看多个文件才能得出的才写。方法签名、导出列表、props 列表、token 具体数值、目录树一律不抄。判据与稳定性排序见契约。
2. **具体接口的 URL、请求/响应字段、枚举不进 `api.md`。** 那是 Story 级契约，事实源在上游设计文档。`api.md` 只装跨需求稳定的通信约定。
3. **不保存秘密或变量值。** 只记录环境变量键名、是否敏感、是否就绪、有无模板默认值；真实值、模板默认值文本、cookie、token、密码都不记录。
4. **不覆盖已有配置。** 可从模板创建缺失的非敏感本地配置；已有 `.env*`、代理或构建配置不得静默改写。
5. **先准备再降级。** 固定执行「发现 → 准备 → 重试 → 证明可用」；没有实际尝试不得写成限制。
6. **只终止本次启动的进程。** 已存在的端口占用者不能擅自结束。
7. **外部副作用先授权。** 下载安装、写业务数据、seed、codegen、登录外部账号、修改已有仓库配置、终止既有进程前请求授权。
8. **每份文件至少一节；不存在的节整节删掉。** 不用「无」「未见」「未声明」「0 个」填版面。但**「无统一做法」是一等公民条目**，必须写成显式规范——它和「有统一做法」一样能决定下游行为。
9. **实证不进 baselines 目录。** 命令退出码、耗时、失败摘要按调用方式落进 `<story-dir>` 或只回话，见门禁 10。
10. **独立调用时实证只回话不落盘。** 无 `<story-dir>` 时无处可落，落进 baselines 会毁掉「契约 vs 实证」这条界线。
11. **不用内容指纹、不写 readiness 字段、不维护 stale 状态。** 跟进方式是消费点自证 + 就地修；覆盖声明负责区分「仓里没有」和「没扫过」。
12. **规范正文只在 app 级。** 不为 Requirement 或 Story 复制规范条目。候选不进九份文件——唯一例外是化石候选（同一反常写法三处以上重复但无解释性注释），它进 `<repo-root>/.learnings/frontend-baseline-candidates.md` 等人工审核，位置在 `frontend-baselines/` 之外，只有本 skill 读写。审核通过才升成规范。
13. **产物不反扫。** 所有发现、引用计数与代码检索排除任意 app 下的 `frontend-baselines/`；baseline 不能成为自己的代码证据。
14. **仓内规范文档只当线索。** 探测到的文档不是事实源：每条陈述要拿去代码里定向验证，进规范节的依据样本填**验证时看的代码**，不填文档章节；验证不了的正文留在文档，只留一条指针清单条目。不从代码样本推断量化上限，不改写用户的文档。

## 工作流

### Phase 0 — 定位、定形态、定首扫范围

1. 定位 `<repo-root>`、`<target-app>`、`<frontend-root>`，按上面的 monorepo 选择规则锁定一个 app，创建 `<repo-baseline-dir>`。“整体生成”时先锁定 app 清单，再对每个 app 从本步独立执行。
2. 若目录已有文件，走[刷新与路由](#刷新与路由)，先归一旧版产物名，不要无条件全量重建。
3. **先定栈签名：框架 + 形态**（`应用` / `微前端宿主` / `微前端子应用` / `小程序` / `组件库`），判据见 `discovery-rules.md`。形态必须在其余文件之前定出来并写进 `structure.md`，因为多组结构判据依赖它——组件库的分层判据整体失效、微前端子应用搜不到请求出口不等于没有、小程序的请求与样式判据都不同。定不出就按 `应用` 处理并在结论里说明。
4. **探测仓内已有的规范文档**（`docs/`、`CONTRIBUTING.md`、`AGENTS.md`、`CLAUDE.md`、`.cursor/rules/`），判据与验证准入见 [discovery-rules.md](references/discovery-rules.md#仓内规范文档是线索不是事实源)。有一个算一个；全没有就静默走原路，不阻塞、不在 baseline 里写「未见文档」。探测放在定范围之前，因为文档里被规范性陈述引用为依据的模块要并进首扫范围。
5. 定首扫范围：`<frontend-root>` 内的**通用层候选目录**（`components/`、`shared/`、`common/`、`ui/`、`lib/`、`utils/` 及其栈内等价物）、**本次已知涉及的业务模块**，以及上一步文档里被引用为依据的模块。允许读取当前 app 实际依赖的 monorepo 共享包作为证据，但不扫描其他 app；任何位置的 `frontend-baselines/` 均排除。大仓不做全量遍历；文档额外带进来的业务模块超过 5 个时列出清单让用户挑。业务侧靠增量长，覆盖声明负责对消费者诚实。

### Phase 1 — 逐问句产出九份文件

按 [references/discovery-rules.md](references/discovery-rules.md) 对每份文件依次回答它的判定问句。规则集是**结构判据**——看导出什么、被谁引用、调用了什么，**不是按文件名里有没有出现某个英文单词**。按名字猜会同时漏掉真资产、又把无关文件吸进来。

取候选时按 Phase 0 定出的框架，读[框架专有标记速查](references/discovery-rules.md#框架专有标记速查)对应的那一行。**判据泛化在「做什么」上，不在「是什么形状」上**——各栈的视图辅助不都是纯函数、请求客户端不都由仓内构造，按别栈的形状去搜会把本该非空的整节判空。

每份文件的产出顺序固定：

1. 在首扫范围内按该文件的结构判据取候选；
2. 逐条**打开代码确认**，写清单条目——指路、一句话「是什么、何时用」、被几处引用；
3. 节头写覆盖声明，声明扫过哪些目录与日期；
4. 从清单归纳规范条目，写规则、依据清单 ID、依据样本、违例判定；**归纳不出统一做法时，把「无统一做法」本身写成规范**。违例判定写成可检索的反向条件（「源码里出现 X 且未满足 Y」），不加「红线」栏——禁止项写进规则那一行；
5. 若 Phase 0 探测到规范文档，把它属于本文件问句的每条陈述拿去代码里定向验证：验证通过的按上一步写成规范、依据样本填看过的代码；与代码不一致的进冲突清单；查不到样本的只留一条指向文档章节的**指针清单条目**，不写成规范；
6. 按[化石判据](references/discovery-rules.md#化石从代码痕迹捉运行时陷阱)捞属于本文件的运行时陷阱：反常写法旁有解释性注释的写成规范；同一反常写法三处以上重复但无注释的只进候选台账；孤例丢掉。化石规范只写现象与正确写法，根因没写在注释里就留空，不许推测；
7. 该文件没有任何内容时整份删掉，不留空壳。

跨关注点场景（表单、i18n、权限、监控埋点、性能预算）**不开文件**，按契约的归置表拆进上面这些文件，靠 `index.md` 的场景索引串起来。运行时陷阱同理，归置表见[契约](references/baseline-contract.md#运行时陷阱归置)。

其余八份写完后写 `index.md`：场景索引、单点事实速查、文件导航，**全部是指向 ID 的行，零事实正文**。场景索引把该场景相关的清单 ID **和** `PATTERN-*` 一并列出——只引清单 ID 会让消费者拿到位置却拿不到约束；但仍然只写 ID，规则正文、陷阱现象、量化数字一个都不抄进来。

全部写完后，若有冲突清单（文档结论与代码归纳不一致），**一轮批量展示让用户裁决**，不按 mtime 猜、不静默采信任何一边。

### Phase 2 — 机器准备与命令实证

主动准备到能开发：

| 缺口 | 默认动作 |
| --- | --- |
| 依赖缺失 | 确认包管理器与 lockfile；需要下载时请求一次授权，执行确定性安装后重试 |
| 本地环境文件缺失 | 从模板生成不含秘密的骨架；敏感键合并成一次请求 |
| 端口冲突 | 先识别占用者；仓内支持安全换端口则换，否则请求用户决定 |
| API / 后端不可用 | 优先启动仓内 mock、MSW、fixture server 或文档声明的本地服务 |
| 需要登录 | 打开可复用会话，让用户只完成登录动作，然后继续验证 |
| 缺测试数据 | 优先使用已有 fixture；seed 会写业务仓或外部数据时先请求授权 |

实跑 `runtime.md` 记录的质量命令，证明它们**可运行**。首次接入允许既有代码失败，但不能用「仓库本来就红」掩盖工具链不可用。

`runtime.md` 只保存命令的 script 名、适用范围、前置条件。本次的退出码、耗时、失败摘要按门禁 9、10 处理。

上表探测到的后端可达方式、契约事实源、测试身份与 seed/reset 入口写进 `runtime.md` 的「服务与身份」节（形状见契约）：只记键名与路径，不记值。这一节是下游 `live` / `contract` 档取证的稳定入口，缺了它每个 Story 都要重新发现后端在哪、能不能写。

完成后停止本次启动且不再需要的进程；若服务要留给紧接着的 `sdd-dev-frontend`，在回话里明确 PID、端口与所有权。

### Phase 3 — 自审

- [ ] `structure.md` 的栈签名给出了一个具名的框架**和**一个具名的形态。
- [ ] 九份文件各自能回答它的判定问句；没内容的整份删了，没有空壳。
- [ ] 全文没有抄来的方法签名、props 列表、token 数值或目录树。
- [ ] `api.md` 里没有具体接口的 URL、字段或枚举；`routes.md` 里没有具体路由路径清单（路由→业务组件索引除外）。
- [ ] 分层判据用的是「消费单元」而不是写死的特性目录；平铺仓也真的判出了分层。
- [ ] `components.md` 写了第三方 UI 库与仓内有没有封装层，或写明本仓不用 UI 库；主题机制正文没有从 `styles.md` 复制过来。
- [ ] 渲染辅助、请求出口、状态容器这几节是按**本栈的框架标记**判的；没有因为本栈的形状与别栈不同（辅助不是纯函数、客户端靠注入取得）而把整节判空。
- [ ] `runtime.md` 的「服务与身份」节写了后端可达方式、契约事实源、测试身份与 seed/reset 入口的键名或路径；否定结论（无 seed/reset、无正式契约）写成了显式条目，没有一个值或秘密。
- [ ] 跨关注点场景没有各自开文件，都按归置表落进现有文件。
- [ ] 每张表都不需要「类型」列来区分内部条目。
- [ ] 每个清单节都有覆盖声明；每个规范条目都有依据清单 ID 与依据样本。
- [ ] 归纳不出统一做法的地方写了显式的「无统一做法」规范，不是留空。
- [ ] 没有 readiness 字段、指纹或 stale 标记。
- [ ] `index.md` 只有指向 ID 的行，且场景索引带上了该场景的 `PATTERN-*`，不只有清单 ID。
- [ ] 没有「红线」栏；违例判定写的是可检索的反向条件，不是「应该遵守规则」。
- [ ] 没有从代码样本推断出来的量化上限（方法行数、圈复杂度、嵌套深度、文件大小、入参个数）；lint 或 CI 配了的指路到配置。
- [ ] 从规范文档来的规范条目，依据样本填的是代码位置而不是文档章节；验证不了的只留了指针条目，且没有按它写违例判定。
- [ ] 用户的文档一个字没改；已迁条目在收尾回话里列了出来。
- [ ] 化石按强证据分流：孤例没有写成规范，三处以上无注释的进了台账而不是规范节，规范里没有推测出来的根因。

## 刷新与路由

先做位置迁移：canonical 目录固定为 `<frontend-root>/frontend-baselines/`。仅当 canonical 不存在时，才检查调用方明确提供或当前工作区唯一可定位的旧外层 baseline 目录：

- 旧目录已是九文件契约：保留正文、ID 与覆盖声明，迁入 canonical 后再走下表；不得长期 fallback 读取旧目录。
- 旧目录只有 `repo-baseline.md` / `onboarding-report.md`：它不能无损转换成九文件契约，在 canonical 完整执行本 skill；旧目录保留为历史备份。
- 新旧同时存在且内容不同：不覆盖、不按 mtime 猜，批量展示冲突并让用户决定。
- “整体生成”逐 app 分别迁移；一个 app 的旧产物不得并入另一个 app。

| 现状 | 动作 |
| --- | --- |
| 目录不存在，或 `index.md` 与 `structure.md` 缺失 | 全量执行 |
| 只有旧名 `routing.md` / `styling.md` / `testing.md` | 一对一迁成 `routes.md` / `styles.md` / `tests.md`，同步 `index.md` 与同目录交叉引用；正文和 ID 原样保留，不重扫。某组旧名与新名同时存在时不覆盖，一轮问清保留哪份 |
| 部分文件缺失 | 先看形态：该形态下本该无内容的（如 `组件库` 的 `routes.md`）就是正确产物，不补；其余只产出缺的那几份，已有文件不动 |
| 消费方报某条清单指路失效 | 只修那一条；这属于 `sdd-task-frontend` / `sdd-dev-frontend` 的就地修权限，通常不必路由到本 skill |
| 消费方报某条规范不再成立 | 由本 skill 重新归纳该规范并更新依据样本；规范节本 skill 独占 |
| 收到 `acceptance.md` 的「规范候选」节 | 按类别处理：`broken` 重新归纳该规范；`new-pattern` 与 `exemption-recurring` **先数复发**——跨 Story 累计到两处以上独立依据样本才写进规范节，只有一处的留在 `acceptance.md` 的候选节里，既不进规范节也不进候选台账（台账只收化石）。复发计数只能在这里做，Story 侧手里永远只有自己那一次 |
| 规范候选里有 `runtime-trap` | **门槛 1 次**，不数复发：白屏或构建行为踩第二次的代价高于误记一条。但**必须附可复现现象**，没有现象就退回去要，不许拿根因猜测落盘。按[归置表](references/baseline-contract.md#运行时陷阱归置)写进对应文件的规范节，现象照抄回传内容 |
| 候选台账里有 `pending` 化石 | 复审：先验证来源样本是否还在。还在且确认不是复制粘贴的升成规范并标 `promoted`；已不在或判定为复制粘贴的标 `rejected`。不删历史条目 |
| 覆盖声明外的新模块要进清单 | 追加条目并同步覆盖声明 |

**不因为某个文件变了就重扫全仓。** 判据是「有消费者读到了不成立的结论」，不是「有文件的内容变了」。

从 `sdd-dev-frontend` 路由而来时，完成后自动返回原 Story，不要求用户再次发起命令。

## 最终输出

```text
✓ sdd-init-frontend
```
