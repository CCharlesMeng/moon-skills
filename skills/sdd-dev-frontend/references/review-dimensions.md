# 检视维度与分级

本文是 Phase C 检视维度、分级与聚合的权威来源。维度是**可选分类法**，不是每个 Story 的必填清单。主 agent 按 [validation-policy.md](./validation-policy.md) 把适用集合写入 `validation_portfolio.review_dimensions`；角色只判断这个集合。

级别只有两档：

- **阻断级**：有足够证据证明某条验收声明不成立，或本次改动已产生具体可复现的错误结果。受影响声明不得写 `PROVEN`。
- **建议级**：有价值、有证据，但尚未证明任何验收声明不成立，也没有当前错误结果。写入 handoff，不自动扩大验证或修复范围。

Open Question 与 Deferred 候选不分级；它们分别代表待决策事项与外部依赖。

## 一、编号体系

| 命名空间 | 含义 | 来源 |
| --- | --- | --- |
| `R1`–`R6` | 还原验收声明的候选分类 | `qa-baseline-template.md` |
| `F1`–`F4` | 功能验收声明的候选分类 | `qa-baseline-template.md` |
| `EX-n` | 已冻结豁免 | `dev-baseline.md` |
| `PATTERN-*` / `REQ-DEC-*` | 仓库范式与 Requirement 工程决策 | `dev-baseline.md / 工程依据` |
| `L1`–`L6` | 布局与响应式维度 | 本文 |
| `C1`–`C7` | 代码规范维度 | 本文 |
| `Q1`–`Q8` | 通用工程质量维度 | 本文 |
| `REG-n` | 验证组合实际选中的回归声明 | `validation_portfolio.claims` |

结论编号是维度加序号，如 `L3-2`、`C6-1`、`Q7-3`。功能自测直接使用已分配的 `F*-n` / `REG-n`，不另造命名空间。

## 二、分级规则

按下列顺序判断：

1. **违反冻结声明**：证据证明某条已冻结 R/F/AC 声明不成立，且未命中 `EX-n` 时，为阻断级。
2. **确证错误结果**：能给出具体操作序列或客观静态反例，且已造成核心流程不可完成、数据错误、核心可访问性失败、竞态覆盖、泄漏或无限循环时，为阻断级。
3. **回归相对起点变差**：只在验证组合已选 `regression` 且有可比起点时，新增失败才是阻断级。没有起点只能写无基线可比。
4. **无基准不判违规**：找不到声明、PATTERN、客观错误结果或其他可核判据时，只可写建议级 / Open Question，或不记。

类型错误、测试失败、还原 RED/YELLOW、硬编码、调试语句、检查抑制、TODO 等都不再是跨 Story 的固定动作门。它们是很强的**风险或缺陷信号**：一旦实际命中验收声明、已选命令或可观察结果，依上述规则升阻断；未命中时不得反向要求新增一整套检查。

## 三、维度分类表

### 3.1 布局与响应式

| # | 维度 | 常见触发事实 |
| --- | --- | --- |
| L1 | 跨页一致性 | 共享样式、跨页组件、同类页对照 |
| L2 | 真实数据溢出与截断 | `required_states` 含 overflow / long-copy / large-list |
| L3 | 目标视口的横向滚动、重叠、截断 | 改布局且 R6 有相关视口 |
| L4 | 对齐与栅格 | 改栅格、对齐或尺寸规则 |
| L5 | 交互状态样式 | 改 hover / focus / disabled / selected / loading |
| L6 | 滚动与固定元素 | 改 sticky / fixed / 内滚容器 |

只取 R6 已冻结且风险闭包命中的视口。上游没有响应式规格时不发明布局结构变化。

### 3.2 代码规范

| # | 维度 | 基准 |
| --- | --- | --- |
| C1 | 目录与文件命名 | 已选 `PATTERN-*` |
| C2 | 组件写法范式 | 已选 `PATTERN-*` |
| C3 | 样式方案与 token | 样式/token `PATTERN-*` |
| C4 | 请求与错误处理 | 请求/错误 `PATTERN-*` |
| C5 | 公共能力复用 | 公共能力 `PATTERN-*` |
| C6 | 类型定义与检查抑制 | 类型/编码 `PATTERN-*` |
| C7 | 国际化与文案机制 | 国际化 `PATTERN-*` |

只分配 diff 实际触碰且没有确定性检查已覆盖的维度。找不到对应 PATTERN 时不用通用最佳实践冒充仓库规范。

### 3.3 通用工程质量

| # | 维度 | 常见触发事实 |
| --- | --- | --- |
| Q1 | 组件职责与体积 | 新增非平凡组件或显著扩大既有职责 |
| Q2 | 重复代码 | 引入新重复或 `shared-boundary` |
| Q3 | 复杂度与嵌套 | 新增复杂分支/循环 |
| Q4 | 状态放置 | 新增共享、派生或跨页状态 |
| Q5 | 副作用管理 | `async-state`、`write`、订阅、计时器 |
| Q6 | 错误与边界处理 | `auth`、`write`、已列 F3 声明 |
| Q7 | 死代码与遗留 | diff 引入占位、不可达代码或调试残留 |
| Q8 | 明显性能问题 | `performance` |

每条质量结论必须说清“什么条件下会产生什么可观察后果”。说不出后果的风格偏好不进报告。

### 3.4 功能自测

`self-test` 不扫固定分类。它只执行 `review_dimensions.self-test` 分配的 `F*-n` / `REG-n`：

- F1：已分配 AC 的测试层级映射；
- F2：已分配 AC 的可观察判定；
- F3：只有基线或风险事实实际列出的异常/边界行；
- F4：只有实际受影响的请求、字段或错误码契约；
- REG：只有回归模块编译出的风险闭包。

## 四、聚合与重跑

1. **覆盖精确匹配**：`status=executed` 时，每个角色的 coverage 必须恰好等于 `review_dimensions` 分配集；不得少判，也不得顺手扩张。`status=unexecuted` 时 coverage 留空并用 known gap 解释，原分配集用于定位哪些声明保持 `UNVERIFIED`。
2. **去重取高**：同一 `canonical_key` 合并，级别取高，保留所有证据与来源编号。
3. **阻断只限受影响声明**：未清零时对应声明保持 `UNVERIFIED`；不把无关声明一并降级。
4. **判断不继承，原始证据按依赖复用**：代码变化后只失效依赖命中的命令、场景、判断与声明。
5. **重编译后再重跑**：修复引入新风险触发器时加入新模块/维度；没有新触发器时只重跑依赖失效的部分。

建议级、Open Question 与 Deferred 候选都必须进 `dev-review.md` 与 handoff，但它们不会自动触发更宽的命令、浏览器矩阵或检视重跑。
