# 上游 `sdd-task` 前端 Task 切分要求

## 这份文档是什么

对 `sdd-task` 产出的 `tasks.md` 在**前端仓**上的切分方式的要求：Task 按什么切、怎么排序、样式文件归谁。`sdd-task` 由上游维护，下游改不到它，所以把要求落成这份说明书，由使用者带到上游照着改。

本文自包含：读完就能改，不需要回头翻 `sdd-dev-frontend` 的任何文件。

- **改动对象**：`sdd-task` 生成 `tasks.md` 的切分规则与模板文案
- **落点**：`tasks.md` 既有的「Task List」节、「文件结构」节、「计划自审三查」节
- **不涉及**：6 步 checkbox 的编号、顺序与 RED/GREEN 语义；后端仓的切分方式；AC 追溯表的结构
- **与 [sdd-task-amendments.md](./sdd-task-amendments.md) 的分工**：那份改的是「Step ① 的失败证据可以是差异清单，一个 Task 内允许多轮 6 步」；这份改的是「Task 本身怎么划分」。两份可以独立落地，一起落地效果最好

---

## 一、为什么要按形态切，而不是按功能点切

前端有两类工作，失败证据的形态不同：

| 工作类型 | 失败证据 | 清零条件 |
| --- | --- | --- |
| 还原（把 HTML 原型的静态呈现落成组件代码） | 与 HTML 原型的差异清单，非空即 RED | 清单清零，或剩余项全部命中已冻结豁免 |
| 逻辑补全（状态迁移、条件渲染、数据变换、接口交互） | 失败的单元测试或单接口集成测试 | 测试转绿 |

差异清单的对照对象是整块原型片段，所以**它只有在「该区块的样式在这一轮全部落地」时才能真正清零**。按功能点切 Task（每个 Task 都带一点样式加一点逻辑）会产生三个后果：

| 后果 | 说明 |
| --- | --- |
| 差异清单反复非空 | 同一区块在后面的 Task 里又被动样式，前一轮已清零的清单失效，证据退化成快照而不是结论 |
| 重复取证 | 每个碰样式的 Task 都要重截原型与实现两张图、重跑一遍六维度比对，成本按 Task 数翻倍 |
| 责任不清 | 一处间距错了，落在哪个 Task 的差异清单里没有定论，每个 Task 都可以说不是自己那轮的事 |

所以：**整页样式集中在一个 Task 里落地，之后的 Task 只加行为、不动样式。**

这与「一个 Task 内允许多轮 6 步」不冲突：**按形态切是首选，多轮 6 步是切不开时的兜底。** 少数区块的样式由运行时状态计算得出、静态形态压根不存在，这种留在逻辑 Task 里走多轮 6 步。

## 二、五条切分要求

每条都给出可直接抄进上游模板的文案。

### 要求 1 — 一个页面的样式集中成一个独立的还原 Task

**落点**：`tasks.md`「Task List」节的切分规则。

**文案**（可直接抄）

> **前端 Task 优先按形态切，不按功能点切：**
>
> 1. 每个页面先出一个**还原 Task**，把该页面全部区块的静态结构与样式一次落完，含五态样式（hover / focus / disabled / 选中 / loading）与空态、超长文案、超多条目的静态呈现。
> 2. 该页面的行为再切成若干**逻辑 Task**，按 AC 分组，一个 Task 覆盖一组紧邻的 AC。
> 3. 同一页面的还原 Task **必须排在它的全部逻辑 Task 之前**。
> 4. **一个 Task 只承担一种形态。** 确实切不开的区块（样式由运行时状态计算得出，静态形态不存在）留在逻辑 Task 里，在该 Task 下注明「本 Task 含还原轮」，按多轮 6 步执行。

**为什么这么写**：第 3 条是物理依赖——行为要挂在 DOM 上，没有结构就没有挂点。第 4 条留的口子必须写明理由，否则「切不开」会变成不想切的挡箭牌。

### 要求 2 — 跨页公共样式与骨架单独一个 Task，排在最前

**落点**：同上。

**文案**（可直接抄）

> 本 Story 涉及多个页面且它们共用布局骨架、公共展示组件或需要新增样式 token 时，先出一个**公共样式与骨架 Task**，排在全部页面 Task 之前，一次落完：新增或改动的 token、公共布局组件、跨页复用的展示型组件。

**为什么这么写**：不单列这一个 Task，第一个页面的还原 Task 会顺手把公共件建出来，第二个页面再按自己的原型改一次，两个 Task 的差异清单互相推翻。

### 要求 3 — 还原 Task 独占样式文件

**落点**：`tasks.md`「文件结构」节，以及每个 Task 的精确文件清单。

**文案**（可直接抄）

> 还原 Task 的文件清单必须列出该页面全部样式文件与组件骨架文件。
> **逻辑 Task 的文件清单不得包含样式文件。** 确有必要时（典型：新增状态类名需要配套样式），在该逻辑 Task 下显式写一行 `越界改样式：<文件> — <原因>`，并注明会影响哪个还原 Task 的差异清单。

**为什么这么写**：文件清单是执行侧「修复动作不出本 Task 的文件清单」的边界。把样式文件的归属写进计划，等于把「谁有权动样式」写死；例外要求显式登记，是为了让被推翻的那份差异清单有据可查，而不是悄悄失效。

### 要求 4 — 还原 Task 必须给出原型来源，区块粒度按「一屏可截」判

**落点**：`tasks.md`「Task List」节，还原 Task 的描述部分。

**文案**（可直接抄）

> 每个还原 Task 逐区块注明对照的原型文件与行号范围。
> **区块粒度的判据是「一次截图能截全」**：在 QA 基线 R6 声明的目标视口下，该区块能在同一滚动位置完整出现在一张截图里，且视觉职责能用一个名词短语说清（「筛选栏」「订单卡片」，而不是「筛选栏和列表区」）。截不全或说不清，按区块边界拆开。
> 一个页面默认一个还原 Task。拆成多个还原 Task 的唯一合法边界是区块边界，触发条件是该页原型分散在多个原型文件、或区块多到一轮差异清单改不完；**不得按「先出骨架、后细化样式」拆成两遍。**

**为什么判据不是行数**：

| 问题 | 说明 |
| --- | --- |
| 行数是代理指标，不是判据 | 同一屏内容在压缩过的 HTML 里可能是 1 行，在格式化过的模板里可能是 400 行；不同规模的需求、不同的原型产出习惯，同一个阈值不可能都合适 |
| 「一屏可截」由取证机制直接推出 | 执行侧 Step ② 要求同视口、同滚动位置各截原型侧与实现侧一张图，逐条指认差异清单。**截不全的区块无法取证**——这条约束跟文件多大无关，是硬的 |
| 真正 load-bearing 的是那条禁令 | 「先骨架后细化」的第一轮差异清单必然非空且必然不清零，而当轮不清零在执行侧是阻断级。这种切法从计划阶段就注定卡住，与页面规模无关 |

行数只作提示，不作判据（可直接抄）：

> 单个区块的行号跨度明显偏大（经验值 200 行以上）时，在该区块下写一行「不拆的理由」。这是提示不是阈值：超过它不一定要拆，但要显式说明为什么不拆。

### 要求 5 — 禁止收尾性质的样式 Task

**落点**：同上。

**文案**（可直接抄）

> 不得产出「样式微调」「统一优化样式」「视觉走查修复」这类 Task。样式偏差的修复归属于它所在区块的还原 Task，当轮清零。

**为什么这么写**：这类 Task 没有可对照的原型范围，差异清单无从产出，Step ① 立不起来。它的实际作用是给前面几轮留一个「以后再说」的出口，而执行侧要求每个还原轮当轮清零。

## 三、落点对照表

| `tasks.md` 章节 | 改什么 |
| --- | --- |
| Task List — 切分规则 | 加入要求 1、2、4、5 的文案 |
| Task List — 每个 Task 的文件清单 | 按要求 3 归属样式文件；逻辑 Task 的越界登记行 |
| 文件结构 | 前端行标明哪些是样式文件、归属哪个还原 Task |
| 计划自审三查 — 前端行另查 | 新增两查，见下节 |

「执行规则」节与 6 步 checkbox 模板**不在本文的改动范围**，那两处的改动见 [sdd-task-amendments.md](./sdd-task-amendments.md)。

## 四、计划自审新增两查

**落点**：`tasks.md`「计划自审三查」节的**前端行另查**部分。三查主干（AC 覆盖 / 占位符扫描 / 类型一致性）与名称都不动。

**文案**（可直接抄，接在前端行既有的另查条目之后）

> 3. 每个页面的样式是否集中在一个还原 Task 内；逻辑 Task 的文件清单是否不含样式文件，例外是否已显式登记。
> 4. 有无「样式微调」「统一优化」这类没有原型对照范围的 Task。

**为什么要有这两查**：要求 1–5 只是把规则写进了模板，没有任何机制保证生成出来的计划真的这么切。漏了不是格式问题——执行侧拿到一份样式散落的计划，会逐个 Task 反复对照同一个区块，差异清单互相推翻，最后卡在收口门禁上。自审是这条链上唯一的拦截点。

## 五、正反例

同一个「订单列表页」Story。

**反例（按功能点切）**

```
T1 订单列表页 — 列表区（样式 + 取数 + 分页）
T2 订单列表页 — 筛选栏（样式 + 筛选逻辑）
T3 订单列表页 — 详情抽屉（样式 + 详情取数）
T4 样式统一优化
```

问题四处：三个 Task 都动样式，跨区块的间距与字号一致性无人负责；T1 清零的差异清单在 T2 加完筛选栏样式后失效；T3 的抽屉与列表区共用的卡片样式归属不清；T4 没有原型对照范围，Step ① 立不起来。

**正例（按形态切）**

```
T1 订单列表页 · 还原
   原型：order-list.html
   区块：页头 L12-L48 / 筛选栏 L50-L132 / 列表区 L134-L286 / 分页 L288-L320 / 详情抽屉 L322-L420
   文件：OrderList/index.tsx、OrderList/index.module.css、OrderList/components/*（骨架）
T2 订单列表页 · 列表取数与分页（AC-1.1、AC-1.2）
   文件：OrderList/index.tsx、api/order.ts、hooks/useOrderList.ts（不含样式文件）
T3 订单列表页 · 筛选与重置（AC-1.3）
T4 订单详情抽屉取数（AC-2.1）
```

T1 一轮还原覆盖全页，差异清单一次成型；T2–T4 只挂行为，不动样式，前面的还原证据不会被推翻。

## 六、改完后如何自查

用一个含前端 Story 的真实输入重新生成一遍 `tasks.md`，逐条核对：

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 形态纯化 | 每个前端 Task 只承担一种形态；含还原轮的逻辑 Task 已注明理由 |
| 2 | 还原 Task 覆盖面 | 每个页面有且只有一个还原 Task（或按区块边界拆出的多个），覆盖该页全部区块 |
| 3 | 顺序 | 同一页面的还原 Task 排在它的全部逻辑 Task 之前；公共样式与骨架 Task 排在全部页面 Task 之前 |
| 4 | 文件清单归属 | 逻辑 Task 的文件清单无样式文件，或例外已按要求 3 登记 |
| 5 | 原型来源 | 每个还原 Task 逐区块给了原型文件与行号范围；区块粒度过「一屏可截 + 一个名词短语说得清」两条，跨度偏大的写了不拆理由 |
| 6 | 无收尾 Task | 全文搜「微调」「优化样式」「走查」，无命中 |
| 7 | 自审条目 | 前端行另查含新增的两条；三查主干与名称未变 |
| 8 | 后端零影响 | 用一个纯后端 Story 生成 `tasks.md`，与改动前的产出逐字一致 |

第 8 条是回归底线：**任何让后端产出发生变化的实现方式都是过度改动**，需要回头收窄。

## 七、下游怎么消费

| 上游产出 | 下游 `sdd-dev-frontend` 的执行方式 |
| --- | --- |
| 还原 Task | 走一轮还原 6 步，差异清单一次覆盖全页，证据落 `alpha-tests.md` 的还原证据记录 `R-<Task 编号>-1` |
| 逻辑 Task | 走一轮逻辑 6 步，证据落 `alpha-tests.md` 的 L4 / L3 记录节 |
| 含还原轮的逻辑 Task | 多轮 6 步，固定先还原轮后逻辑轮 |

**没按本文切的 `tasks.md` 照样能执行**：下游不改 `tasks.md` 的内容，退回「一个 Task 内多轮 6 步」执行。代价是同一区块被多轮反复对照、已清零的差异清单可能被后面的 Task 推翻，取证成本按碰样式的 Task 数翻倍。
