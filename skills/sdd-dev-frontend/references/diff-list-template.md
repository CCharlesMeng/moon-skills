# 差异清单模板

还原轮 Step ① 的失败证据。**非空即 RED，清零即 GREEN。** 为什么还原类工作用它而不是 DOM 断言测试充当 RED 证据，见 [ADR-0001](../docs/adr/0001-restore-uses-diff-list-as-red-evidence.md)。

**一轮一份，一份对一个区块。** 一个 Task 内有几个还原轮就有几份，不合并。

## 这份清单在 6 步里的位置

| Step | 对本清单做什么 |
| --- | --- |
| ① RED | 按 R1–R6 逐维度产出清单，清单非空 |
| ② 验 RED | 逐条到两侧截图上指认；指不出来的项删除并写明原因 |
| ③ GREEN | 逐项改，只改清单里有的 |
| ④ 验 GREEN | 逐条填「GREEN 复核」栏，结论只有清零与全部命中已冻结豁免两种 |
| ⑥ 落账 | 按第五节的映射抄进 `alpha-tests.md` 的「还原证据记录」节 |

## 一、填写栅栏

模板的目的是逼出**可判定的偏差描述**。三道栅栏都要过，任何一条不过则该行不合格，退回重写。

### 栅栏 1 — 槽位填满

每条偏差是一行八列，缺任何一列都不成立。

| 列 | 要求 |
| --- | --- |
| 偏差编号 | `D-R<维度号>-<序号>`，序号在本份清单内从 1 起编 |
| 维度 | `R1`–`R6` 之一，逐字沿用 QA 基线的维度名 |
| 基线依据 | 本条偏差违反的 QA 基线期望值编号，如 `R1-2`；QA 基线未覆盖到时写 `无对应期望值` 加一句说明 |
| 元素 | 偏差落在哪个元素上。区块内的具体控件、文案、容器，不写「整个区块」 |
| 偏差项 | 差在哪。一句话，能被判成「已消除」或「未消除」 |
| 原型表现（期望值） | 原型侧的具体取值 |
| 实现表现（当前值） | 实现侧的具体取值，与上一列**同一属性、同一量纲** |
| 取证方式 | 在哪儿能看到这处偏差 |

「原型表现」与「实现表现」必须成对可比。只写一侧（「间距是 16px」）无法判定改到什么程度算完。

**基线源不是 HTML 原型时**（`dev-baseline.md` 基线头登记为 `参照页 <路由>` 或 `文字规格`），「原型表现」一列读作**基线侧表现**，取值来自参照页的实测值或文字规格 + `S-n` token；列名与八列结构不变，截图文件名也不变（`red-prototype.png` 存的是基线侧那张）。成对可比这条要求不因基线换源而放宽。

### 栅栏 2 — 措辞黑名单与必含要素

偏差项、原型表现、实现表现三列出现以下措辞即不合格：

| 禁用措辞 | 为什么不合格 |
| --- | --- |
| 间距不对 / 样式有出入 | 没点名元素，没有两侧取值，改完无法判定是否消除 |
| 与原型不一致 / 未按原型实现 | 整份清单写的就是不一致，等于没写 |
| 略有偏差 / 基本一致 / 差得不多 | 「略」「基本」是可伸缩的口子 |
| 整体观感不同 / 视觉重量偏轻 | 主观词，第三方无法证伪 |
| 多处间距需调整 / 若干文案有出入 | 不点名，改一处也能算做完 |
| 疑似缺少某某 / 好像少了一块 | 没查清就落笔，Step ② 必然指认不出来 |

两侧取值至少命中以下一类：

| 类型 | 例 |
| --- | --- |
| 数值 | `24px` / `1.5rem` / `4 个` / `24 字符` |
| token 或枚举名 | `--spacing-lg` / `--color-bg-hover` / size `small` |
| 逐字文案 | 「全部状态」 / 「共 {n} 条」 |
| 可观察状态 | 悬停变深一档 / 悬停无变化 / 点击后按钮转 loading |

### 栅栏 3 — 陌生人指认测试

自问：**一个没参与本轮的人，只拿这一行和那两张截图，能不能自己把这处偏差指出来？**

指不出来，就是没写完。这一条兜住前两道栅栏漏掉的情况——措辞不在黑名单里、也有数字，但仍然指不到具体位置。Step ② 是这道栅栏的实际执行点。

### 编号说明

偏差编号从维度编号派生，带 `D-` 前缀，**在本份清单内从 1 起编**，如 `D-R1-1`、`D-R3-2`。

`D-` 前缀用来与 QA 基线的期望值编号（`R1-1`、`R3-2`）区分。前缀加在偏差侧而不是基线侧，是因为期望值编号被 QA 基线、检视维度清单、AC ↔ 证据映射多处引用，是稳定的规格侧；偏差编号一轮即作废，加前缀成本为零。

两套编号**不要求一一对应**：期望值是 Story 级，一个维度下若干条期望；偏差是「一轮一区块」级，一个维度下若干条实际偏差。需要指向 QA 基线的某条期望值时，写在「基线依据」列，直接写期望值编号，如 `R1-2`。完整定位一条偏差用「记录编号 + 偏差编号」，形如 `R-T3-1 / D-R1-1`。

## 二、清单头

字段与 `alpha-tests-restore.md` 的记录头逐字对应，Step ⑥ 原样搬运。

| 字段 | 值 |
| --- | --- |
| 记录编号 | `R-<Task 编号>-<轮次>`，如 `R-T3-1` |
| Task | `tasks.md` 中的 Task 编号与标题，注明第几轮与形态 |
| 区块 | 原型切分表中的区块名，**逐字沿用，不得改写** |
| 原型来源 | 原型文件路径 + 行号范围，与切分表一致 |
| 截图视口 | 宽 × 高，取自 `dev-baseline.md` 环境段声明的目标视口 |
| 可信度 | 仅降级时填 `降级（源码级对照）`，否则整行不出现 |

区块名逐字沿用切分表，是为了保证同一区块在勘察、实现、检视三个阶段被理解成同一个东西。

## 三、差异清单主体

**六个维度必须逐行出现，按 R1→R6 排列。** 无偏差的维度保留该行，偏差编号与两侧取值填 `—`，偏差项写「无偏差」。同一维度有多条偏差就拆成多行。

| 偏差编号 | 维度 | 基线依据 | 元素 | 偏差项 | 原型表现（期望值） | 实现表现（当前值） | 取证方式 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | R1 区块与层级完整性 | | | | | | |
| | R2 文案一致性 | | | | | | |
| | R3 间距与对齐 | | | | | | |
| | R4 状态样式 | | | | | | |
| | R5 空态与边界内容 | | | | | | |
| | R6 指定视口下的布局完整性 | | | | | | |

### 各维度的偏差项要点名什么

| 维度 | 必须点名 | 正例（原型 ↔ 实现） |
| --- | --- | --- |
| R1 区块与层级完整性 | 缺失 / 多出 / 错位的元素名，以及数量与排列顺序 | 缺少「重置」按钮：搜索框右侧并排「查询」「重置」两个按钮 ↔ 只有「查询」一个 |
| R2 文案一致性 | 逐字给出两侧字串，含标点、单位、大小写；动态文案给模板串 | 状态下拉占位文案：「全部状态」 ↔ 「请选择」 |
| R3 间距与对齐 | 哪两个元素之间、哪条基准线，以及数值或 token 名 | 筛选行与列表区的垂直间距：24px（`--spacing-lg`） ↔ 16px |
| R4 状态样式 | 哪个元素的哪一态（hover / focus / disabled / 选中 / loading），以及触发方式与可观察变化 | 「查询」按钮 hover：背景变深一档至 `--color-primary-hover` ↔ 无变化 |
| R5 空态与边界内容 | 触发条件的具体数值（条数、字符数），以及两侧的具体表现 | 订单名 24 字符以上：单行省略号截断 + hover 出 tooltip ↔ 换行撑高行 |
| R6 指定视口下的布局完整性 | 视口宽度 + 破在「不破」三项（横向滚动 / 重叠 / 内容截断）的哪一项 + 具体元素 | 1280px 下操作列：完整显示三个按钮 ↔ 「导出」按钮被裁切一半 |

R6 只记「不破」三项的破损。**上游没有响应式规格时不得在此记录布局结构差异**，需要改变布局结构的诉求记为 Open Question 回问上游。

### 取证方式列怎么填

| 情形 | 写法 |
| --- | --- |
| 常规 | `截图 red-prototype.png / red-impl.png 的<位置>`，位置要具体到区块内哪一处 |
| 降级 | `源码级对照：原型 <文件> L<起>-L<止> ↔ 实现 <文件> L<起>-L<止>` |

### GREEN 复核

Step ④ 填。偏差编号与上表一一对应，无偏差的行不进本表。

| 偏差编号 | 处置 | 复核结果 |
| --- | --- | --- |
| | | 已清零 / 命中豁免 `EX-n` |

复核结论只有两种合法形态：

1. **清零**——清单每一项都已消除。
2. **剩余项全部命中已冻结豁免**——每个剩余项列出它命中的 `EX-n`，该豁免必须在确认门冻结的 QA 基线中已经存在。

**开工后新增豁免来消化剩余项，等同于放宽标准**，必须走 `dev-baseline.md` 变更记录并重新请用户确认，不得在本清单就地追认。除这两种之外的任何状态（还剩几项、下轮再改、影响不大）都不是 GREEN，属阻断级。

GREEN 侧另附实现截图一张，原型截图沿用 RED 的同一张。

## 五、落账映射

Step ⑥ 按下表把本清单收敛进 `alpha-tests.md` 的「还原证据记录」节。左侧是本清单的列，右侧是账本的列。

| 本清单 | → | `alpha-tests.md` 还原证据记录 | 说明 |
| --- | --- | --- | --- |
| 清单头五个字段（降级时六个） | → | 记录头同名字段 | 原样搬运，字段名不变 |
| 偏差编号 | → | 偏差编号 | 原样 |
| 维度 | → | 维度 | 原样 |
| 元素 + 偏差项 | → | 偏差项 | 合并成一句，如「缺少「重置」按钮」 |
| 原型表现（期望值） | → | 原型表现 | 原样 |
| 实现表现（当前值） | → | 实现表现 | 原样 |
| 基线依据 | → | 不入账 | 工作列，用于证明判据来自冻结基线；落账时基线追溯由 AC ↔ 证据映射承担 |
| 取证方式 | → | 不入账 | 工作列，收敛为 RED 双方截图两行；降级时其中的文件与行号范围写进截图字段 |
| RED 双方截图 | → | RED 双方截图 | 原样 |
| GREEN 复核表 | → | GREEN 复核 | 原样，三列同名 |

不入账的两个工作列**不得因此省略不填**——它们是 Step ② 和 Step ④ 的执行依据，没有它们这两步无从做起。

- [ ] 每条的「原型表现」与「实现表现」是同一属性、同一量纲的一对具体取值
- [ ] 每条至少命中数值、token 或枚举名、逐字文案、可观察状态之一

- [ ] 清单非空；为空时已回头核对过精读范围与六个维度
- [ ] 截图两侧同视口、同区块、同滚动位置；降级时两行都写了 `降级：源码级对照`
