# sdd-dev-frontend

把上游 `tasks.md` 和 HTML 设计稿真正跑成前端代码：按 Task 走 6 步 TDD、拿冻结的设计契约当还原证据、四路并行检视，最后交出一条可追溯到验收标准（AC）的证据链——而不是「看起来做完了」。

## 适用场景

- 一个前端仓、一个 Story 的 `tasks.md` 已经就绪，要开始实现；
- 按 HTML 原型 / 参照页 / 文字规格三档之一还原页面样式；
- 续跑其中某一步：重抽设计稿、重跑某份检视、补视觉证据……
- **不会自动触发**，必须在对话里明确点名。

## 怎么用

### 简化版本——`tasks.md` 已就绪，路径能自动定位

```text
请使用 sdd-dev-frontend 执行 Story <编号>。
```

### 复杂版本——没有 `tasks.md`，需求刚在这次对话里聊清楚

```text
请使用 sdd-dev-frontend 执行 <Story 名>。

目标前端仓：<repo-root>
Story 目录：<story-dir>
还没有 tasks.md，请按我们刚才聊的内容自动起草，起草完先给我确认。
```

路径给得越全，首次定位时来回确认越少；没有 HTML 原型时可以直接说明改用参照页还是文字规格。

## 会发生什么

全程静默推进，只有一处必须停下等你确认：**QA 基线确认门**——它定义「怎样算做完」，你确认后冻结，之后每一步都拿它当证据标准，中途要放宽必须重新经过你确认。完成时给出三行索引，指向汇总了全部证据的 `dev-review.md`。
