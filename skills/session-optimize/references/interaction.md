# 交互规范：逐字照抄的输出格式

`SKILL.md` 的「交互」一节已就地说明 P1（一轮一个决策点）、P3（不解释流程）、P5（三行索引收口）、P6（零决策阶段内联）在哪一轮生效。本文件只给四件事：三个必须逐字照抄的格式，和一条不写就会退回散文的约束。

## P2 — 结构优于散文

多项内容一律用表格或列表。纯散文只出现在单行摘要，不超过 2 句。

模糊邀请语要换成明确的行动指令。它名义上把决定权交给用户，却不说怎么行使，用户通常什么也不做，确认门就形同虚设：

| 不要写 | 写成 |
| --- | --- |
| 以上是你最终会得到的东西。如果和你的预期不一致，现在是最好的纠正时机。 | `→ 请确认继续 / 或指出需要修改的地方。` |

## P4 — 确认门与批准门格式

有门的阶段统一以这四行结束，字面照抄：

```text
---
**[Phase N 确认门]** <本阶段产出的一句话描述>
→ 请确认继续 / 或指出需要修改的地方。
---
```

门之后不追加"如果…可以…"的补充说明：追加的那句自己就是一个新决策点，一轮于是有了两个（P1）。

## P5 — 三行索引

执行完成时只输出这三行。不重新摘要刚才交互过的内容，不拆成"设计摘要 / 产出文件 / 下一步"几个子章节——用户刚参与完那些交互，重述一遍只是让他再读一次自己说过的话：

```text
✓ <skill 名> 完成
产出：<文件路径>
下一步：<一条具体指令>（附触发条件，如适用）
```

## P7 — 批量提问

同一优先级的问题合并在一轮，不拆成多轮一个个问。用表格给出，每题标明必答还是可跳过：

```text
以下 N 个问题需要你回答：

| # | 问题 | 我的推测（如有） | 必答 |
| --- | --- | --- | --- |
| Q-1 | ... | — | 是 |
| Q-2 | ... | 推测为 X，理由：... | 否，可确认、纠正或跳过（跳过则标为工作假设） |
```

不用段落文字引导用户回答，不在每个问题后写单独解释。
