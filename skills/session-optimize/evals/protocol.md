# 评测与轻量验收

本轮按用户明确要求采用轻量验收，不以全量模型回归作为交付条件。保留 68 个行为用例供后续按风险抽样，不默认启动全套重复重放。

## 轻量验收

1. 校验 evals.json 格式、ID 唯一性和修改文件的引用、格式。
2. 对照正文与 references，检查证据不足、批准条件、台账更新是否一致。
3. 检查代表性记录：能够区分已证实偏差与未定根因；不对缺乏具体材料的修法请求批准；有独立依据的局部纠正仍可申请。
4. 涉及委派边界时，使用一次真实干净子代理检查基线先于轨迹、历史指令隔离及原因保留。明确实际完成的阶段，不用文字模拟代替运行证明。

## 模型抽样的证据要求

- 用例与断言先于正文改写冻结，合成夹具不是本机项目事实。
- executor 只见正文、必要引用和该例 prompt，亲自记录原始输出。写入类行为在只读重放中给出位置及具体内容即可，不要求真的改项目。
- 若使用 grader，只提供断言和原始记录，不提供 skill、evals 或主 Agent 摘要。缺失记录记未验证。
- 三次多数与全量盲评仅在明确需要扩展验证时使用。同模型一致不证明根因；拟议委派不证明实际隔离。
- 输出放在被忽略的 runs/ 下。已中止或未完成的执行不得计入通过；记录验收范围，不把轻量抽样称为全量回归通过。
