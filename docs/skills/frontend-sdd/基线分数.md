## 一、准入规则

| 模块类型 | 准入条件 |
| --- | --- |
| 确定性脚本 | 全部 unittest 通过，且用例数不减。改了行为的，先改测试并在下表记明为什么 |
| 判定类提示词 | 四项分**每项都不低于**下表当前值，且四项都在及格线内。跑 3 次取最低那次 |
| 编排 | `evals.json` 存量用例全过，新增用例跑 3 次取多数不复发 |

**跑 3 次取最低**，不取平均也不取多数：判定类提示词的失败方式是偶发漏检，平均会把它抹平，而漏检一次在真实使用里就是一次漏检。

### 首轮那两条已修复并验证

两处提示词修改在 `4456465`（抽出 review 包）时落地：`quality-lens/ROLE.md` 加了「同一检查项内部也要穷尽：找到一条大的性能问题后继续找同项里较小的第二条」，`quality.md` 的 Q4 加了「『更新后有一帧不一致』**不得**升 P0/P1：次帧闪烁不是确证的功能缺陷」。但当时没有重新打分，所以本文档一直把它们记成待办。2026-08-24 补跑三次验证：

- **GT-6（Q8：`sort` 未缓存）从 3 次全漏变成 3 次全中。** 三次都在报出「500 条无虚拟化」之后继续报了「每次渲染重新排序」，即同一维度内部不再找到一条就收敛。

### 格式合规掉到 0.833，但它是一条坏的度量

三次里只有一次失分，失分项是第四节第 6 条（「coverage scope 写明 diff 取法（第 1 条）与改动文件数 4」）。查过之后这条**把两件性质完全不同的事捆在了一起**：

- **有真实价值的那半**：`judged_files` 要覆盖被判的改动文件。失分的那次（run A）只列了 2 个文件（`HoldingsTable.tsx`、`useHoldings.ts`），而 diff 有 4 个（另有 `App.tsx` 与 `HoldingsTable.module.css`）。代价是实际发生的：它因此完全没看 CSS，而另一次跑在那个文件里报出了一条真发现（三个语气类声明逐字相同，导致六种行语气里有三种视觉上无法区分）。
- **不该计分的那半**：说出「第 1 条」和「4」这两个数字。`review-quality.md` 与 `review-convention.md` 的前置表都只写「Story diff 可取 | `<base-ref>`；缺失时取…并集」，**没有任何一处要求把用了哪一条叙述出来**。查过 `4456465` 删掉的内容，旧版同样没有。所以首轮的 6/6 是模型自愿叙述出来的，不是提示词要求的——**首轮那个 1.00 和本轮这个 0.833 是同一个噪音的两面**，不是回归。

`convention-02` 的格式合规 0.857 也卡在同类问题上（三次都对命中 `EX-1` 的那行保持沉默，没留下核对痕迹），两处指向同一个结论：**格式合规这一项里凡是「要求留痕/叙述」的条目，都必须在提示词里明写，否则测的是运气。**

两条候选修法，都还没做：把叙述要求写进两份 agent 卡片的输出格式节（一行，让这项变成确定的）；或者把 GT 第 6 条拆开，只保留 `judged_files` 覆盖那半。**改提示词要重新跑 3 次才能记分**，所以本轮只记测量结果与诊断，不动提示词。

### 顺带暴露的一个机制缺口

`judged_files` 现在只有下限（非空）和上限（必须是 `code.files` 的子集），**没有完整性要求**——一个角色实际判了四个文件却只声明一个，聚合器照样放行，而它的判断从此几乎不会被任何修复失效。run A 声明 2/4 就是这个形态的实例。这条不是 `review-quality` 的问题，是回传契约的问题，记进[模块与评测的优先级表](./模块与评测.md)待办。

### 两条可能是 ground truth 缺口的新发现

run B 报出两条不在 GT 任何清单里的发现，看着都站得住，留给下一轮修 ground truth 时判断要不要收进必报项：CSS 里三个语气类声明逐字相同（`.toneMuted` / `.toneFrozen` / `.toneClosed` 都只有 `color: var(--color-text-secondary)`），使 `getRowTone` 五层分支算出的六个结果里三个渲染一致；以及 error 分支整体早退会把地区筛选下拉一起卸载，用户无法在页内换回正常地区，只能刷新。
