User guide · Frontend delivery workflow

从 tasks.md
到可验收的前端交付

sdd-dev-frontend 把一个独立前端 app 中的一个 Story，执行成代码、RED → GREEN 证据、并行检视和可追溯的最终结论。

上游任务与设计 + 冻结 QA 基线 + 逐 Task 证据 = 可验收交付
1 × 1 一个独立前端 app × 一个 Story
10 冻结的 QA 基线维度
6 每一轮固定执行步骤
4 完成后的并行检视

End-to-end workflow

每个 Phase 都把明确产物交给下一步

点击任一阶段查看它的职责、交接物和你需要参与的动作。正常情况下， 唯一固定的人工作业点是 Phase A 的 QA 基线确认门。

Task topology · 样式还原

先集中落样式，再让逻辑接上来

“样式还原”首先决定 Task 怎样切、样式文件归谁，不只是 Task 内的一次还原轮。 目标是让冻结外部设计契约一次整体 GREEN，并让后续逻辑不再推翻已 GREEN 的机器证据。

条件 Task · 多页面共享时

公共样式与骨架

一次落完新增或修改的 token、公共布局组件和跨页复用的展示组件。

拥有
共享 token / 公共骨架 / 展示组件
交接
稳定的跨页视觉底座
→
默认 Task · 每个页面一个

页面还原

一次落完全部区块的静态结构、样式、五态、空态与边界内容呈现。

拥有
页面样式文件 / 组件骨架
交接
RED / GREEN 报告 + 机器盲区人工目视项 + R-记录
→
重复 Task · 按 AC 分组

逻辑 Task × N

接入状态迁移、条件渲染、数据变换与接口交互，原则上不再碰样式文件。

拥有
行为代码 / API / hooks / 测试
交接
L4 / L3 逻辑证据
01 共享骨架在最前 有跨页共享内容时，先于全部页面 Task 落地。
02 一页一次还原 默认每页一个还原 Task，不拆成“骨架 / 细化”两遍。
03 还原独占样式 逻辑 Task 的文件清单不应包含样式文件。
04 区块可独立取证 原型文件 + class 锚点；一屏可截、一个名词说清。
05 没有收尾样式 Task “样式微调 / 统一优化”不能替代同一契约无 RED、无 YELLOW。

逻辑 Task 必须越界改样式时

在 Task 下显式登记 越界改样式：文件 — 原因，并注明受影响的还原 Task 或 R-记录。对应 GREEN 证据随即失效，相关区块必须重新对照和取证。

既有 GREEN→失效→重新取证

拿到的 tasks.md 没有这样切

本 skill 不改写上游计划，而是退回“同一 Task 内多轮 6 步”：固定先还原、后逻辑。 流程仍可执行，但同一区块会重复运行契约，后续样式改动也会推翻早先结论。

不要和 Phase C 混淆 样式还原属于 Phase B，负责让逐区块冻结契约无 RED、无 YELLOW；布局与响应式检视属于 Phase C， 是完成后的只读复核，关注跨页一致性、真实数据、多视口与交互态，不能代替还原 Task。

Phase B

同一套 6 步，支持两种失败证据

上游已按形态切分时，还原 Task 只跑还原轮、逻辑 Task 只跑逻辑轮。 只有没有切开时才在同一 Task 内固定先还原、后逻辑；两类轮次沿用相同的 6 步编号。

RED 运行冻结契约
验证 RED 核出处 + 补 YELLOW
GREEN 按清单最小改动
验证 GREEN 同契约全绿 + 回归
REFACTOR 仅在 Task 边界内
记录并提交 落账到 alpha-tests.md
机器报告至少一项明确 RED 才进入实现；无 RED、无未解决 YELLOW 才是 GREEN。
本轮证据归宿

还原证据记录

一区块一轮，只记录契约与报告指纹、三色摘要、可选视觉缓存和实现截图。

Traceability

证据沿同一条链从 AC 追到最终验收

tasks.md 只管进度，alpha-tests.md 只管证据， acceptance.md 只管最终检视；三者各自唯一，不另开第二本账。

AC 锚点 上游声明要交付什么
tasks.md AC 由哪些 Task 覆盖
RED → GREEN 逻辑测试或冻结还原契约
alpha-tests.md L4 / L3 / 还原记录与状态
acceptance.md 各路检视、阻断项与收口结论
验收状态 GREEN 或 Deferred；没有模糊第三态

Phase C → D

独立视角汇总后，阻断级必须清零

检视全部只读、同轮并行，派哪几路由本次验证组合决定。 检查项与定级来自 sdd-review-frontend；本 skill 只选角色、备证据、汇总去重并保留证据。

Artifact ownership

产物按生命周期分层，不混进代码仓

Requirement 级工件只随设计稿内容哈希失效；Story 级工件随 Story 变更失效； 代码仓只承载实际实现和测试。

Requirement 级 设计稿事实，可跨 Story 复用
design-inventory.md → design-facts.json → block-index.md → blocks/*.md
Story 级 判定、进度、证据与检视
dev-baseline.md → dev-baseline.md / 工程依据 → tasks.md → alpha-tests.md → acceptance.md evidence/
目标前端仓 随 PR 交付的实际变更
组件代码 样式与 token 使用 单元 / 集成测试 接口与类型改动

Human checkpoints

大部分时间自动推进，决策点才打断你

同类问题会批量合并，不逐条消耗注意力。没有决策的阶段直接内联到下一次有决策的输出。

路径冲突 四个关键路径无法唯一定位时一次问完。
Phase A 确认门 确认 QA 基线、豁免与基线来源。
连续修 3 次失败 同一报错不再盲目尝试。
需要越界改动 Task 文件清单或 Story diff 范围之外要授权。
收口决策 阻断项、Open Question、Deferred 候选合并询问。
最终三行索引 给出产物路径和唯一下一步。

Visible degradation

缺能力可以降级，缺失不会被伪装成通过

降级改变的是证据强度或可执行范围，不会静默放宽你已经确认的 QA 基线。

没有 HTML 原型

基线来源按可用性逐级下降。

优先找 2–3 个仓内参照页候选
由你确认具体参照路由与区块
仍不可用则改用文字规格 + token
最终状态标明“非原型对照”

不能截图或起页面

不允许用源码阅读冒充视觉与行为实测。

不能截图：机器可检项照常；visual 保持 YELLOW
不能起页面：只跑 static；render-required 保持 YELLOW
布局检视记为未执行
起不了页面时功能自测试也未执行
最终结论显式限定可信度

接口或外部依赖不可用

跑不了的 AC 不能变成“基本通过”。

功能项记录“未跑（具体原因）”
主 agent 判断是否满足 Deferred
写明外部依赖与解除条件
Deferred 不计为已验收

Resume & re-entry

中断后按事实恢复，不从头重来

进度、规格缓存、基线确认和检视结论有不同的复用规则。Story 变更时才重新勘察并再次确认。

tasks.md checkbox 决定起点 从第一个未完成 Task 继续，不另建第二本进度。
设计规格按区块内容哈希复用 只重抽变化和新增区块，不按 mtime 让整份设计稿失效。
Story 未变时复用已冻结基线 不要求你对同一份 QA 基线确认两次。
检视结论一律重跑 代码已经变化，旧的 acceptance.md 结论不能复用。 
请继续运行 sdd-dev-frontend，
从上次中断的位置接着做。

也可以只说：
· 重抽设计稿规格
· 只做代码侧勘察
· 重跑布局检视
· 只跑功能自测试
· 重跑全部检视并重新收口

Exit gates

“代码能编译”远远不是完成

只有进度、差异、回归、证据和检视全部闭环，才会输出最终三行索引。

1
Task 全部完成6 步 checkbox 无遗漏、无批量补勾。
2
还原报告无 RED、无 YELLOW或未匹配项逐条命中已冻结豁免。
3
阻断级为 0修复后失效的检视判断已经重跑。
4
未清零阻断不牵连无关声明它只把自己命中的那条声明保持未验证。
5
回归没有变差与 DEMAND-2 的 test / typecheck / lint / build 起点逐项对照。
6
AC 证据可追溯每条 AC 都能追到真实 RED / GREEN 或实测记录。
7
Deferred 没被洗成通过原因和解除条件齐全，且不计入已验收。
8
未执行检视显式披露报告与最终状态都说明缺了什么、为什么。
