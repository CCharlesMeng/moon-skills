## 三、Requirement 设计事实

### `design-facts.json`

确定性机器事实，包含原型指纹、资源内容哈希、设计 token、静态文案、布局声明、覆盖缺口和 `blocks[]`。区块只保留 `content_sha256`；`structure` 继续供 R1 事实读取。原型仅格式化不改变原型指纹，资源内容变化会改变指纹。

### `design-inventory.md`

唯一的人读清单，把 token、静态/动态文案和重复界面模式合在一个文件。文档哈希一致时保留人工审订；哈希变化时重写。它不做仓内 `PATTERN-*` 映射。

### `block-index.md` 与 `blocks/`

脚本候选段已经职责单一时，主 agent 从切片头直接写区块索引。只有候选段需要跨段归并时才派 `extract-prototype`。单区块切片超过 12,000 字符或用户点名时才派 `extract-block-spec` 并生成 `blocks/<区块>.md`。

主 agent、`recon-spec` 与检视角色不直接读取原型正文。争议只回查一个区块并登记。

## 四、冻结还原链

### `restore-contract.json` v3

顶层只保留 `schema_version`、`baseline_sha256`、`contract_sha256`、`rules`。一条规则只能是：

| 形态 | 判据 |
| --- | --- |
| render | `check_mode` + `expected`；`overflow` / `overlap` / `clip` 用 `tolerance` 作阈值 |
| static | `static_check` |
| exempt | `frozen_exemption.id` + `reason` |

每条规则带 `id`、`baseline_id`、`subject`；可选 `scenario` 自由字符串和顶层布尔 `fixture_required`。编译器保留五个硬保护：冻结字面、基线 SHA、基线行覆盖与 ID 唯一、render 期望非空、采集结果链接同一契约。既有 v2 契约继续可读，新编译只产 v3。

A2 通过 stdin 输入规则，不落一份与契约重复的草稿：

```bash
python3 <skill-dir>/scripts/verify_restore_contract.py contract \
  --baseline <story-dir>/dev-baseline.md \
  --rules - \
  --out <evidence-dir>/restore-contract.json
```

基线变化后重新确认，再加 `--after-reconfirmation`。脚本在覆盖前把活动报告改名为 `.stale-<旧契约sha8>.json`，冲突时追加序号，不覆盖历史。

### `restore-adapter.json`

只保存实现定位。render 规则写任意顺序的 `locators[]` 与 `collect`；static 规则只需 `source_files[]`；exempt 不写 adapter 行。随机构建 class 只告警。adapter 不复制外部期望。

### RED / GREEN 报告

报告顶层保存契约链接键、实际 `observed.viewport` / `route`、三色汇总与逐规则条目。RED 就地保留 `expected`、`actual`、`comparison`、`reasons`；字符串不等附人工排查序列化的 `hint`。GREEN 条目只留规则 ID、状态和实际值；冻结豁免留豁免 ID。

新建页面在实现前不存在时免 RED，并在 `alpha-tests.md` 明记。GREEN 行保存当时完整代码指纹；C 阶段当前指纹与它一致时直接复用，缺值或变化时重跑全部冻结区块并覆盖同一 GREEN 文件。聚合器读取 GREEN 报告并机械把 R1–R6 的 RED/YELLOW 映射为 blocker，不派额外还原角色。

图片焦点与透明叠层观感等机器盲区不进入契约；拆成保留原 R 行追溯的 `manual_acceptance`，在人工验收入口列明路由、目视动作与证据要求，真实人员回填前保持 `UNVERIFIED`。

## 五、Story 账本、检视与收口

### `dev-baseline.md`

Phase 0 写执行起点与初始验证组合；A2 合并工程依据、功能理解、适用 QA 行、豁免、已知缺口和确认记录。`tasks.md` 是实现进度真相，基线不保存实现进度。

### `alpha-tests.md`

声明状态和证据索引的唯一账本。还原记录固定为五列：轮、契约 sha8、报告文件、三色、说明；不抄契约/报告的 64 位指纹或逐规则报告，GREEN 说明里的完整代码指纹是 Phase C 复用判定所需的唯一例外。还保存 AC ↔ 证据、人工验收、Deferred 和计划外承接。

### `review-evidence.json`

只保存验证组合、代码状态、命令与 scenario 原始事实，不保存 pass/fail 或 finding。scenario 使用 `page`、`fixture`、`viewport`、`steps`、`observations`、`artifacts`、`depends_on`、采集时依赖哈希与 runtime 作为核心字段；多消费者和接口接缝字段按需添加。复用按依赖和 runtime 精确失效，不因无关文件变化整包作废。

### `review-results.json` 与 `acceptance.md`

`aggregate` 校验 0–4 份被选角色结果，合并同 `canonical_key` 的发现，并直接并入最终还原报告。结构化全量结论写 `review-results.json`；给人的摘要整文件覆盖到 `acceptance.md`，不手写追加。

## 七、脚本索引

| 脚本 | 子命令 / 作用 |

| `extract_design_spec.py` | `extract`、`block`、`blocks`；生成两份设计事实与按需切片 |

## 八、不变量

1. 人读 Markdown 在 Story 根；机器 JSON 与正式证据在 `evidence/`；可重算过程件在 `.work/`。
2. 冻结期望只来自已确认基线；实现值只进入 actual 与 adapter。
3. RED 与 GREEN 使用同一 `contract_sha256`；YELLOW 不改写成 GREEN。
4. 一份事实可以多方消费，但角色判断不互相泄漏。
5. `PROVEN` 必须有新鲜证据；人工验收必须由真实人员回填，agent 不代签。
